# 个人办公工作台 · Personal Workbench

一个**零依赖、单文件、可离线**的个人办公工作台。整个应用就是一个 `index.html`——双击即可使用，数据默认存在浏览器本地，可选与云端表格双向同步。

> 面向个人自用场景，不依赖任何构建工具、框架或后端服务。

---

## 特性

### 12 个视图，覆盖日常工作流

| 视图 | 用途 |
|---|---|
| 今日焦点 | 一屏汇总今日待办、逾期项、学习打卡状态，快速进入当天节奏 |
| 搜索 | 跨任务／笔记／专项／检查／日程／个人事项的全局检索，支持范围与时间过滤 |
| 今天待办 | 四象限优先级任务，支持子项、标签、截止日期、批量操作 |
| 检查任务 | 面向「检查／巡检」类工作的目标、阶段、下一步、阻碍项跟踪 |
| 日程管理 | 月／周视图网格，支持跨天事项与颜色分类 |
| 个人事项 | 独立于工作的个人清单，带分类与优先级 |
| 学习计划 | 每日学习打卡，记录时长、内容与专注度分块 |
| 学习数据 | 学习时长趋势与维度雷达，按周汇总折叠 |
| 灵感速记 | 轻量笔记，支持置顶与标签 |
| 专项跟进 | 项目／专项分组看板，汇总下属任务进度 |
| 每周复盘 | 周维度回顾：完成量、逾期、专注分布 |
| 数据说明 | 存储占用、云端同步状态、导入导出、清空与损坏数据留档 |

### 稳定性设计

- **本地优先**：`localStorage` 是唯一真源，断网、无账号均可完整使用
- **双向同步**：可选接入云端表格，7 张表共用一条同步流水线
- **冲突处理**：`本地ID` 认身份 + `更新时间` 后写胜出（LWW）+ 墓碑软删除
- **损坏自愈**：读取失败不清空，原始串自动留档，可在「数据说明」中下载
- **跨标签同步**：`StorageEvent` 即时同步，多标签同时打开不会互相覆盖
- **零依赖**：无 npm、无 CDN、无构建步骤，浏览器直接跑

## 快速开始

### 方式一：本地打开（最简单）

下载 `index.html`，双击用浏览器打开即可。数据保存在当前浏览器的 `localStorage`，换浏览器／清除站点数据会丢失，请定期用「数据说明 → 导出」备份。

### 方式二：部署为网页

把 `index.html` 放到任意静态托管（GitHub Pages、对象存储、内网服务器）即可。仓库根目录已按 GitHub Pages 约定放置 `index.html`。

### 关于云端同步

云端同步依赖宿主页面注入的 `window.__SMART_PAGE__.database` 接口。**单独打开 `index.html` 时该接口不存在，应用会自动进入纯本地模式**，除同步相关按钮外功能完全可用。

## 数据模型

本地键：

```js
localStorage['pd_workbench_v2']   // 主存档，JSON
```

存档结构：

```js
{
  tasks: [], notes: [], projects: [], inspects: [],
  schedules: [], personal: [], study: [],
  pcats: [], meta: {}
}
```

云端 7 张表（任务／专项／笔记／检查／个人事项／学习／日程）共用同一套列契约。以个人事项为例，**9 列固定契约**：

| 列名 | 类型 | 说明 |
|---|---|---|
| 标题 | text | 业务主键之一 |
| 优先级 | number | 1–4 |
| 截止日期 | date | 可空 |
| 是否完成 | checkbox | 完成态 |
| 分类 | text | 分类名 |
| 备注 | text | 自由文本 |
| 本地ID | text | **身份锚点**，跨端认同一行靠它 |
| 更新时间 | number | 毫秒时间戳，**LWW 依据** |
| 已删除 | checkbox | 墓碑标记，不物理删除 |

同步策略：

1. 以 `本地ID` 匹配两侧记录
2. 两侧都有 → 比较 `更新时间`，新者胜出
3. 仅云端有且本地无 → 拉入本地（`已删除` 为真则记为墓碑，不复活）
4. 仅本地有 → 推送到云端
5. 无 `本地ID` 的历史行 → 按业务键（标题 + 日期）认领一次，之后补齐 `本地ID`

## 项目结构

```
.
├── index.html              # 全部源码：内联 CSS + 原生 JS，约 8300 行
├── docs/
│   ├── AUDIT-REPORT.md     # v31 审计报告（调研／问题清单／变更详情／风险／验证）

```

`index.html` 内部分区：

| 区块 | 内容 |
|---|---|
| `<style>` | 设计令牌（CSS 变量）+ 全部样式，含明暗主题 |
| 状态层 | `S`（业务数据）、`ui`（界面状态）、`KEY`（存储键） |
| 工具层 | `T()` 双语、`esc()` 转义、日期计算、`uid()` |
| 归一化 | `normalize()`、`load()`、`save()`、`rollover()` |
| 同步层 | `CloudSync`：`pullAll` / `pushAll` / `merge` / `resig` |
| 视图层 | 12 个 `vXxx()` 纯函数返回 HTML 字符串 |
| 事件层 | 单一委托 `onClick` / `onInput`，按 `data-act` 分发 |

## 审计与版本

v31 是一次完整的静态代码审计修复版本：**37 处定点修复，无架构级重构，无新增依赖**，全部改动行以 `// modified` 注释标注（共 116 处）。核心修复是一个会**清空全库**的启动崩溃：

```js
// 原代码：keep 是 Set，却调用了 Map 的 .get()
S.study = S.study.filter(x => x && x.date && keep.get(x));   // 抛 TypeError

// v31：改回 Set.has()
S.study = S.study.filter(x => x && x.date && keep.has(x));   // modified
```

只要存在任意一条学习打卡记录，旧版启动即抛错 → 回退空库 → 立刻写回本地，数据不可逆丢失。

详细问题清单、修复思路、风险与验证步骤见 [`docs/AUDIT-REPORT.md`](docs/AUDIT-REPORT.md)，逐行改动见 [`docs/v31.diff`](docs/v31.diff)。

## 兼容性

- 现代浏览器（Chrome / Edge / Safari / Firefox 近两年版本）
- 需要 `localStorage`；隐私模式下可用但数据不持久
- `crypto.randomUUID` 需安全上下文（https / localhost）；`file://` 打开时自动降级为时间戳 + 随机数
